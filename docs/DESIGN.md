# NeoNote Rust移植 設計書

2026-10-26

## 設計理念と製品情報

理念は「とにかく軽く早く、省クリック数で動く」こと。機能を足すか迷ったときは、この理念と下の「やらないこと」を基準に判断する。

### 位置づけ

- 艦長（作者）が自分用に開発した、メモ帳替わりのコードエディタ。
- 用途はメモ書きから軽いコーディングまで。数クリックで終わる作業に VSCode や Eclipse のような重い IDE を出すのが面倒なときに使う。
- 特にマイクラユーザー向け。JSON 整形機能を追加する予定。
- キャッチコピー：「軽量、高速、省クリック数でただ文字を書くために最適化されたツール」。英語版は *Only for Writing. Light. Fast. Clickless. Tuned to be yours.*

### やらないこと（ノンゴール）

- IDE のような重量級の機能（プロジェクト管理、補完、デバッガ、プラグイン基盤など）を足さない。
- 最近の Microsoft メモ帳のように、メモ帳に必要のない煩雑な機能を足さない。
- AI 機能を足さない。
- あくまで「純粋なエディタ」を保つ。
- 例外として、作者の判断（2026-10-25）で**上部のタブ**は採用した（複数ファイルをまたいだ編集のため）。範囲は後述の「タブ機能」節の最小限に限る。その後、作者の依頼（2026-10-25）で **検索バーの常駐・タブの並べ替え・セッション復元** も採用した（「第12段階」参照）。分割表示などは今も入れない。

### この理念からの設計上の帰結

- 依存最小・単一バイナリ・起動が速いことを最優先する（fltk-rs を選んだ理由とも一致）。
- クリック数を減らす：開く・保存・エンコーディングは最短手順にする。設定画面やダイアログを増やさない。
- 新機能の採用基準：「メモ書きを速くするか」「マイクラの JSON を直すのに直接役立つか」のどちらかを満たすこと。満たさないものは入れない。
- メニューに「見た目だけ」の項目を先行して置く方針（下の機能対応表）は、このノンゴールに反しない範囲で行う。実装しないと決めたものは外す。

### 技術方針：ネイティブ実装と高速動作（必須要件）

「軽く早く」を実現するため、実装方式について次を守る。これは機能の取捨より上位の制約で、違反する提案は採用しない。

- **禁止**: Electron、Tauri などの WebView 系、CEF、ブラウザエンジンの内蔵、WebGL / OpenGL などの GPU 描画層を画面表示のために使うこと。HTML / JS で UI を組むことも含む。
- **採用**: OS ネイティブ寄りの軽量ツールキット（fltk-rs）で UI を描く。依存は `fltk`・`encoding_rs`・`pulldown-cmark`（md の Preview 用）のみ、単一バイナリ、ランタイム同梱なし。
- **プレビュー**: アプリ内にブラウザエンジンを持たない。fltk の HelpView で足りる簡易表示か、OS の既定ブラウザへ渡すかのどちらかにする。
- **速度の基準**: 起動が体感で即時であること。大きなファイルでも読込でウィンドウが固まらない（非同期読込）こと。編集・検索・置換・エンコーディング判定・HEX 変換は GUI スレッドを長く塞がないこと。
- **コードの置き方**: 重い処理（文字コード判定、HEX 変換、全置換）は `neo/` に置き、1パスで済ませる。不要なコピーや全文の再取得を避ける。
- **新しい依存を足す条件**: 上の禁止事項に当たらず、起動時間とバイナリサイズへの影響を確認できること。

### プロダクト説明（作者の原文を記録）

> 艦長が自分用に開発したコードエディタ。メモ帳替わり。全てのファイル構造を解析して自動でエンコード方式を選ぶ機能付き！（バイナリも読めます）

### 追加したい要素（作者の要望）

- ボタンと、テキスト画面の右クリックメニューのオプション。
- 整形機能（JSON など）。
- プレビュー機能（HTML や Markdown など）。

### 位置づけの追加

- あくまでテキスト「エディタ」であり、エクスプローラー系ソフトと併用する前提。ファイルツリー、フォルダ管理、ファイル操作は持たない。
- 機能は拡張できる構造にする。ただし拡張の入口は「ツールバーのボタン」と「右クリックメニューの項目」の2つに限る。

### 上の要望からの設計上の帰結

- メニューとボタンは、ラベルと動作を1か所に登録する表（`MenuEntry`）で管理する。新機能は表に1行足すだけで、ボタンと右クリックの両方に出せる。これが「拡張できる構造」の実体で、プラグイン基盤は作らない。
- 整形とプレビューは、開いている文書を入力として結果を返す関数にする（`fn(&str) -> Result<String, Error>` の形）。エディタ本体に組み込まず、メニューの1項目として呼び出す。
- プレビューはエディタ内に常設の分割画面を作らず、必要なときだけ別ウィンドウで開く。fltk の HelpView は簡易な HTML しか描画できないため、Markdown は変換してから表示する想定。完全なブラウザ表示が必要な場合は OS の既定ブラウザに渡す。どこまで描画するかは未確認事項に追加。
- 整形（JSON）は、プレビュー（HTML・Markdown）より優先度を高くする。マイクラ向けの用途に直結するため。

## 概要と確定した設計判断

SwingNeoNote（Java/Swing、847行の単体メモアプリ）を、依存を最小にした Rust 製の別プロセスアプリへ作り直す。ゲーム側は `neonote [パス...]` を起動するだけにする。

| 項目 | 決定 |
| --- | --- |
| 最優先要件 | 依存が少ないこと。次に、多くの OS・バージョンで動くこと |
| GUI 基盤 | fltk-rs（TextEditor が行番号・ハイライト・IME を内蔵。ビルドに cmake と C++ コンパイラが必要） |
| ゲームからの起動 | コマンドライン引数のみ。ドロップごとに新規プロセス・新規ウィンドウ（既存ウィンドウのタブに入れるには単一インスタンス化が必要で、未実装。「タブ機能」節を参照） |
| 未実装メニュー（約30項目） | 見た目だけ先に残し、動作は後から実装する |
| Run In CMD | 確認なしで、Java 版と同じ挙動のまま残す |
| Java 版の癖・バグ | 全面的に作り直す（ボタン構成・メニュー体系も整理） |
| HEX モード | 編集可能な HEX エディタ。保存はバイト列として書き込む |
| 開発者判定 | `user.name == nemo`（大文字小文字無視）ならバージョンを v999.99.9 にする条件を維持 |
| 文字コード変換 | `encoding_rs` を1つだけ追加（Shift_JIS 等のため） |
| macOS | Java 版は非対応だったが、Rust 版は対応する |

仕様の出典は `admin/java/SwingNeoNote.java`（本体）、`admin/java/Log.java`（ログ）、`admin/java/FileDropHandler.java`（呼び出し側）の3ファイル。

## クレート構成とモジュール分割

単一バイナリのクレートを1つ作る。ロジック（ファイルI/O・文字コード・HEX変換・ログ）を GUI から分離し、GUI なしでテストできる形にする。元の Java は 847 行の単一クラスに全部が混在していた。

```text
neonote/
├─ Cargo.toml            依存: fltk, encoding_rs の2つのみ
└─ src/
   ├─ main.rs            起動引数の解釈、ログ初期化、ウィンドウ起動
   ├─ app.rs             ウィンドウ・イベントループ・状態（現在ファイル・変更フラグ）
   ├─ ui/
   │  ├─ theme.rs        配色定数（COLOR_MAIN / SUB / TEXT / ACCENT）
   │  ├─ toolbar.rs      ツールバー8ボタンと右クリックメニュー
   │  ├─ editor.rs       TextEditor、行番号、検索ハイライト
   │  └─ context_menu.rs 編集領域の右クリックメニュー
   ├─ neo/
   │  ├─ document.rs     読込・保存・未保存変更の管理
   │  ├─ encoding.rs     UTF-8 / Windows-31J / ISO-8859-1 / US-ASCII
   │  ├─ hex.rs          バイト列↔HEXテキストの変換とパース
   │  └─ replace.rs      全置換（単一パス）
   ├─ platform.rs        OS別のブラウザ起動・フォルダを開く・シェル実行
   ├─ dev.rs             開発者判定（user.name）
   └─ log.rs             Log.java 互換の極小ロガー
```

分割の考え方は次の3点。

- `neo/` は fltk を一切 import しない。文字コードや HEX のバグを GUI 抜きでテストできる。
- `platform.rs` に OS 分岐を集める。Java 版で `os.name` を複数箇所で判定していたものを一箇所にまとめる。
- 依存は `fltk`・`encoding_rs`・`pulldown-cmark`（stage 17 で追加）のみ。ログ・起動引数・プロパティ読込は自前で書く（数十行で済む）。

## HEX エディタとエンコーディング・ファイル I/O

HEX モードは「バイト列を持ち、画面には HEX テキストを出し、保存時にバイト列へ戻す」という形で作り直す。Java 版は読込時に文字列化するだけで、保存すると HEX 文字列そのものをファイルに書いていた。

### HEX エディタの仕様（提案）

- **表示形式**: 1行16バイト。`オフセット  HEX×16  ASCII` の順。行番号欄にはオフセットを出す。
- **編集対象**: HEX 部分のみ。ASCII 欄とオフセットは表示専用で、編集後に再生成する。
- **パース**: 保存時に、HEX 欄から「0-9A-Fa-f の2桁」だけを拾ってバイト列を作る。空白・改行は無視する。
- **パース失敗**: 奇数桁や HEX 以外の文字があれば保存を中止し、最初の不正箇所の行・列を示してカーソルをそこへ移す。ファイルは書き換えない。
- **巨大ファイル**: 上限を設ける（仮に 16 MiB）。超えた場合は先頭だけ読み、保存は無効にして破損を防ぐ。

### テキストモードのエンコーディング

| エンコーディング | 実装 | 備考 |
| --- | --- | --- |
| UTF-8（既定） | Rust 標準の `String` | 不正なバイト列は置換文字にせず、読込時に警告する |
| Windows-31J（CP932） | `encoding_rs`（`SHIFT_JIS`） | 実体は Windows-31J。Java 版の「Shift_JIS」表示は同名の別方式ではなく、実際の方式名に直した。JIS 標準のみの Shift_JIS は扱わない |
| ISO-8859-1 | `encoding_rs`（windows-1252 で代用するか自前） | 自前は1バイト=1文字なので数行で済む |
| US-ASCII | 自前 | 0x80 以上は警告 |

- エンコーディングを切り替えるときは、開いているファイルを**ディスクから読み直す**（Java 版と同じ）。未保存の編集がある場合は確認を挟む。Java 版は確認なしで編集内容を捨てていた。
- 保存時に指定エンコーディングで表現できない文字があれば、保存前に警告する（Java 版は黙って `?` に置換）。
- ファイルの書込は一時ファイルに書いてからリネームする。書込中の失敗で元ファイルを壊さないため。
- ウィンドウを閉じるときはドキュメントを「バイト列として保持」しておき、モードに応じて表示を作る（テキスト↔HEX の切替はバイト列経由）。

## ログ・起動引数・ゲーム連携・開発者判定

### 起動引数とゲーム連携

```text
neonote [--log-level <DEBUG|INFO|WARN|ERROR>] [パス...]
```

- 引数なしなら空のウィンドウを開く。パスが複数ある場合は先頭だけを開く（複数ファイルを同時に開きたいときは、ゲーム側がプロセスを複数起動する）。
- パスが存在しない場合は、Java 版と同じくエラーダイアログを出して空のウィンドウを表示する。
- Java 側の `FileDropHandler.open()` は、`ProcessBuilder` で `neonote <パス>` を起動する形に置き換える。これにより、「macOS では Swing がクラッシュする」という `IS_MAC` ガードと、EDT 経由の `invokeLater` が不要になる。
- 拡張子の振り分け（`.txt` / `.md` / `.json` → 本アプリ）は引き続きゲーム側の責務とする。

### ログ

`Log.java` と同じ表記を自前の小さなモジュールで再現する。

- 出力形式：INFO / DEBUG は `[Tag] msg`（stdout）、WARN / ERROR は `[WARN] [Tag] msg` / `[ERROR] [Tag] msg`（stderr）。
- レベルの決定順：起動引数 `-log-level` → `mod/log.properties` の `log.level` → 環境変数 `NEO_LOG_LEVEL` → INFO。Java 版の `-Dneo.log.level` は Rust に対応するものが無いため省く。
- Java 版では `-log-level` を `LaunchArgs.is(...)` で判定している。このクラスは zip に無いため、ゲーム共通の引数表記（`-log-level` と `--log-level` の両方を受けるか）は要確認。仮に両方受ける。
- `Log.fileName()` は表示専用のヘルパーとしてそのまま移す（`/` と `\` の両方を区切りとして扱う）。

### 開発者判定

- `dev.rs` に `fn is_dev_user() -> bool` を置き、`USER` / `USERNAME` 環境変数が `nemo`（大文字小文字無視）なら true。
- true のときバージョン表示を `v999.99.9` にし、`[alert] 開発環境のためスキップ` を INFO で出す。
- Java 版のコメントにある「判定条件を README 等に文書化しない」方針を引き継ぎ、この設計書以外の配布物に条件を記載しない。ただしバイナリに文字列 `nemo` が残ることは Java 版と同じ。読み取られにくくしたい場合はハッシュ比較へ変える選択肢もある。

## 移植手順、リスク、未確認事項

実装は6段階で進める。各段階の終わりで「開いて、編集して、保存できる」状態を保つ。

1. **骨組み**: cargo プロジェクト、`log.rs`、`dev.rs`、起動引数、空のウィンドウ（タイトルバーと配色を含む）。
2. **テキスト編集の基本**: TextEditor、行番号、開く・保存・非同期読込、未保存確認付き終了、ドロップ受付。
3. **エンコーディング**: `encoding.rs`、切替 UI、変換不能文字の警告、安全な書込（一時ファイル→リネーム）。
4. **右クリックメニューとツールバー**: Replace、Search、Search In web、Run In CMD、パスのコピー、グレーアウトのメニュー項目。
5. **HEX エディタ**: `hex.rs`、表示形式、パースとエラー位置へのジャンプ、バイト列としての保存。
6. **フォント・アイコン・README と、Java 側の置換**: リソースの埋め込み、`FileDropHandler.open()` を別プロセス起動へ変更。

### リスク

| リスク | 影響 | 対策 |
| --- | --- | --- |
| fltk-rs のビルドに cmake と C++ コンパイラが必要 | ビルド環境の準備が必要。ここでは Rust だけで完結しない | ビルド手順を README に書く。静的リンクで配布する |
| Linux での日本語入力（X11 では XIM、Wayland ではアプリ側の対応が必要な場合がある） | IME が効かない環境が出る可能性 | 主要ディストロで実機確認する。第2段階で早めに検証 |
| TextEditor の柔軟性（色・フォント・行番号の見た目の自由度が Swing より低い） | Java 版の見た目を完全には再現しない | 配色と主要なレイアウトを優先し、細部は許容 |
| 絶対パスやフォントフォルダの OS 差 | Windows のパスをハードコードしていた箇所が Linux / macOS で壊れる | `platform.rs` で必ず分岐。第4・6段階で各 OS を確認 |
| Run In CMD が確認なしで選択文字列を実行する | 誤操作・悪意あるファイル経由の実行リスク（「そのまま残す」という決定を尊重して維持） | 設計上は確認を入れられるよう、フラグ 1 つで切り替える構造にしておく |

### 第4段階で決めたこと（実装メモ）

- メニューの表は `ui/menu.rs` の `MenuEntry`（`action: None` はグレー表示で押せない）。設計の構成図にあった `context_menu.rs` は作らず、右クリックメニューも同じ表（`CONTEXT`）で持つ。ツールバーは `ui/toolbar.rs`。
- ボタンは左クリックで主な動作、右クリックでメニュー。Edit は実装までグレー。Run は Run In CMD に統合した。ボタンの文字は絵文字ではなく英字（fltk のフォントで絵文字が出る保証がないため）。
- Java 版の「Cancel」項目は置かない（メニューの外をクリックすれば閉じるため、クリック数が増えるだけ）。
- パスのコピーは、ツールバー右の余白をクリックする。ダイアログは出さず、余白に短く「Path copied」と出す。保存先が無いときは何もコピーしない（Java 版は代わりにホームページの URL をコピーしていた）。
- Replace は全文を 1 回だけ読み、1 回の編集として書き戻す。「元に戻す」1 回で全て戻る。置換結果の中は再走査しない。
- Search は最初に使ったときだけスタイルバッファを作る（使わなければ負荷ゼロ）。何も選ばずに Search すると、ハイライトを消す。
- Search In web は `http://` / `https://` で始まり空白を含まないものだけ URL として開く。それ以外は Google 検索。シェルを通さずに OS の標準手段で開く。失敗したらホームページを開く。
- Run In CMD は確認なし（決定どおり）。`app.rs` の `CONFIRM_RUN_CMD` を true にすると確認が入る。選択ありならバックグラウンドで実行し、標準出力と標準エラーを「実行結果」に出す。選択なしならカレントフォルダを開く（結果ダイアログは出さない。Java 版は空のダイアログを出していた）。
- エンコーディング切替を、右クリックメニューと Run ボタンのメニューの「Change Encoding」から呼べるようにした。
- fltk-rs では、既定だと標準の処理が先に走る。右クリックを自前で処理するため、編集領域とボタンは `super_handle_first(false)` にしている。
- 手元の Cargo が 1.75 だったため、`Cargo.lock` で `encoding_rs 0.8.34`（fltk は 1.5.23）に固定してビルドを確認した。新しい Cargo なら `cargo update` で上げてよい。

### 第5段階で決めたこと（実装メモ）

- `neo/hex.rs`: `format`（バイト列→表示）と `parse`（表示→バイト列、不正なら行・列・位置を返す）。往復と不正位置をテストした。
- 1 行は `オフセット(8桁)  HEX×16  |ASCII|`。行頭がオフセットとして読めない行（8 桁の 16 進でない）はエラーにする。オフセットを消した行を黙って捨てて、データを失わないため。
- オフセットは行番号欄ではなく本文に出した（fltk の行番号欄は行番号しか出せない）。
- バイナリ判定されたファイルは、エラーではなく HEX で開く。`Ctrl+E` のメニューに HEX を追加し、切り替えるとディスクから読み直す（未保存の編集があれば確認する）。保存先の無い文書は HEX にできない。
- 保存は一時ファイル→リネームでバイト列を書く。成功後はオフセットと ASCII 欄を作り直す（その時点で「元に戻す」の履歴は消える）。
- 上限 16 MiB（`hex::MAX_BYTES`）。超えたら先頭だけ読み、保存は無効にして警告する。

### 第6段階で決めたこと（実装メモ）

資料（`icon.png`、`/source/font.ttf`、`/source/README`）が zip に無いため、第6段階は「資料が要らない部分」だけを実装した。残りは下の「第6段階の積み残し」。

- **フォント選択**: `Font`（Load と Run。以前の `Open Settings` / `Choose Font`）から `Action::ChooseFont` を呼ぶ。`.ttf` / `.otf` を選ぶと、編集領域・行番号・Search のハイライトに適用する（Java 版は本文と行番号のみ）。初期フォルダは `platform::font_dir()`（Windows は Java 版と同じ `%USERPROFILE%\AppData\Local\Microsoft\Windows\Fonts`、macOS は `~/Library/Fonts`、Linux は `~/.local/share/fonts`。無ければホーム）。
- 読み込めないファイルは、原因を含むエラーを出して元のフォントのまま。キャンセルは何も起きない。
- fltk-rs の `App::load_font` は読んだフォントを固定の枠（番号 16）に入れるため、一度に使えるのは選んだ 1 つだけ。選び直すと置き換わる。`Font::load_font`（enums 版）は名前の一覧に登録しないので使わない（`by_name` が既定フォントに黙って落ちる）。
- 選んだフォントは設定ファイル（後述「設定ファイル」節）の `font=` に保存し、次の起動でも使う。読めないときは警告して同梱の NeoFont で起動する。
- **Java 側の置換**: `admin/integration/java/FileDropHandler.java`。`open()` を `ProcessBuilder` で `neonote <絶対パス>` の起動に置き換え、`SwingNeoNote` / `SwingUtilities` の import、`IS_MAC` ガード、`invokeLater` を削除した。`admin/java/` の元ファイルは触っていない。
  - 実行ファイルの探索順: `-Dneo.neonote.path` → 環境変数 `NEONOTE_PATH` → `mod/neonote(.exe)` → PATH 上の `neonote(.exe)`。**`mod/` に置く前提は仮置き**（ゲーム側の配置が未確認）。
  - パスは必ず絶対パスにして渡す（先頭が `-` のファイル名をオプションと誤認させないため）。
  - NeoNote の標準出力・標準エラーはゲームの出力へそのまま流す（「デバッグしてほしい」要件）。作業フォルダと環境変数を引き継ぐので、`mod/log.properties` と `NEO_LOG_LEVEL` はそのまま効く。
  - 起動に失敗したら `Log.error` とチャット通知（`gui.drop_open_failed`）を出す。macOS でも同じ経路で動く。
  - 実ゲームのクラスが無いため、`Log.java`（実物）とスタブで `javac -Xlint:all` が警告なしで通ること、実際に neonote が起動し空白や先頭 `-` を含むパスを開くこと、実行ファイルが無いときの失敗通知を確認した。ゲーム本体との結合は未確認。

## 同梱フォント（NeoFont）

作者の指示で、`NeoFont.ttf`（約 10 MB）を既定のフォントとして同梱する。他のフォントは従来どおりパス指定（Load・Run の `Font`）で読み込む。

- `assets/NeoFont.ttf` を `include_bytes!` でバイナリに埋め込む（`platform.rs`）。バイナリはその分（約 10 MB）大きくなる。
- FLTK はメモリからフォントを読めない（ファイルのパスが要る）。起動時に `<一時フォルダ>/neonote-font-<バージョン>/NeoFont.ttf` へ展開して `App::load_font` で読む。同じ内容が既にあれば書き直さない。壊れていれば書き直す。書き出しは一時ファイル→リネーム。
- `App::load_font` は枠 16 に入れる仕様なので、パス指定で読んだフォントは NeoFont を置き換える。一度に使えるのは 1 つだけ。選んだフォントは `font=` に保存するので、次の起動でも使う。
- 展開や読込に失敗しても起動は止めず、エラーをログに出して Courier で続ける。
- Linux（Xvfb）で、NeoFont で本文と行番号が描画されること、日本語が表示されることを確認した。Windows / macOS は未確認。
- **クレジット**: NeoFont は作者（nemo）の自作フォントなので、同梱に権利上の問題は無い。README とこの文書に作者を明記する。
- **既定フォントに戻す**: Run の右クリックメニューの `Default Font`（`Action::ResetFont`）。展開済みの NeoFont を `load_font` で枠 16 に読み直して適用する。

## タブ機能（第6段階のあとに追加）

作者の判断で、メモ帳（Windows 11）のような上部のタブを入れる。目的は「複数ファイルをまたいで編集しやすくする」ことだけ。「やらないこと」にある新メモ帳風の煩雑さを持ち込まないため、範囲を次に限る。

### 範囲

- 入れる: タブバー（ファイル名、未保存の `*`、閉じる `×`、新規 `+`）、タブの切替、タブごとに独立した文書。
- 入れない: タブの分割・別ウィンドウ化、タブ一覧のドロップダウン、タブの右クリックメニュー。要望が出たら、そのとき方針として決める。
- 当初は入れないとしていた「タブの並べ替え」と「セッション復元」は、後から採用した（「第12段階」）。

### 動作の決定

- 文書ごとに、本文（TextBuffer）・パス・文字コード・BOM・HEX モード・変更フラグ・カーソル位置・Search のハイライトを持つ。切り替えても「元に戻す」の履歴は文書ごとに残る。
- 開く（ダイアログ、起動引数、ドロップ）は新しいタブで開く。ただし今のタブが「空で未保存の新規」なら、そのタブを使う（空のタブが残らないように）。すでに開いているファイルなら、そのタブへ移る。
- 起動引数・ドロップで複数のパスが来たら、全部をタブで開く（以前は先頭だけ。タブがあるので制限する理由が無くなった）。
- 文字コードの切替・HEX への切替は、今のタブをディスクから読み直す（従来どおり。未保存なら確認）。
- タブを閉じるとき、未保存なら 保存 / 破棄 / キャンセル。最後のタブを閉じたらアプリを終了する（Windows のメモ帳と同じ）。ウィンドウの ×・Exit は、未保存のタブを順に確認し、1つでもキャンセルされたら終了しない。
- ショートカット: `Ctrl+T` 新規タブ、`Ctrl+W` タブを閉じる（macOS は Cmd）、`Ctrl+Tab` / `Ctrl+Shift+Tab` で次・前のタブ（macOS でも Ctrl）。タブの中クリックでも閉じる。
- タブの幅は、並べたときにウィンドウに収まるよう縮める（最小 50px、最大 220px）。ウィンドウ幅の変更に追従する。最小幅でも収まらないほど多いときは、選ばれているタブを含む範囲だけを表示する（隠れたタブは `Ctrl+Tab` で現れる。一覧のドロップダウンは作らない）。
- 「開く」ダイアログは複数選択でき、選んだ全てをタブで開く。最初のものを表示する。
- タブを閉じたら、右隣（無ければ左隣）のタブを表示する。
- 実装: `ui/tabs.rs`（タブバーの部品）、`app.rs` の `Doc`（文書ごとの状態）。タブの作り直しはメインループで行い、ボタンのコールバックの中では行わない（押されたボタン自身を消さないため）。ラベルの `&` と `@` は FLTK が特別扱いするので重ねて無効にしている。
- Search のハイライト用バッファは、いずれかの文書で Search を使うまで作らない（使わなければ負荷ゼロ、は維持）。使ったあとは、切り替えた先の文書にも作る。
- 検証済み（Xvfb + xdotool）: 複数引数と重複の検出、`Ctrl+Tab` / `Ctrl+Shift+Tab` / `Ctrl+T` / `Ctrl+W`、中クリックで閉じる、未保存タブの閉じる確認（保存 / 破棄 / キャンセル）、ウィンドウ×での未保存確認、11 タブでの幅の縮小とリサイズ、Search のハイライトが文書ごとに保たれること。未検証: ファイルのドロップ（xdotool で再現できないため）、Windows / macOS。

### 未解決: ゲームからのドロップ

ゲームは今もドロップごとに `neonote <パス>` を別プロセスで起動するため、**ゲームからのドロップは新しいウィンドウになり、既存ウィンドウのタブには入らない**。タブに入れるには、すでに起動している NeoNote へパスを渡す仕組み（単一インスタンス化。ローカルソケットやロックファイルなど）が要る。依存を増やさず std だけで書けるが、起動の軽さと複雑さに影響するため、まだ着手していない。必要か作者に確認する。

| Make Shortcut | デスクトップに NeoNote のショートカットを作る | Linux: `~/Desktop`（無ければホーム）に `NeoNote.desktop`。Windows: PowerShell で `NeoNote.lnk`（デスクトップの場所は OS に問い合わせる）。macOS は未対応でエラーを出す |

### 履歴（View History / Restore From History）

「履歴」は**過去に読み込んだファイルのパス**の履歴（作者の判断 2026-10-25）。以前の「保存のたびの内容のスナップショット」は廃止した。`neo/pathlog.rs`。

- 記録するタイミングは Open Recent と同じ（ファイルを開いた・保存したとき）。新しい順、同じパスは先頭へ移す、**最大 100 件**。設定ファイル自身は入れない。
- **終了後も残す**: `config.txt` の `history=パス` に 1 行ずつ保存する（設定ファイルの節を参照）。Open Recent（`recent=`、最大 10 件）とは別の一覧。
- **View History**: 別ウィンドウに `1  ファイル名` の形で一覧し（ファイル名のみ。60 文字を超えるものは先頭 40 文字 + `…` + 末尾 19 文字に省略して拡張子を残す）、行をダブルクリック（または Enter）するとそのファイルをタブで開く（すでに開いていればそのタブへ移る）。100 件はポップアップメニューに収まらないので、スクロールできる一覧ウィンドウにした。ウィンドウの大きさは中身に合わせる（幅は一番長い行に合わせて 240〜560 px、高さは行数に合わせて最大 12 行で、超えたら縦スクロール。横スクロールは出さない）。開いている間、元のボタン（Undo）はアクセント色で強調し、ウィンドウの上端にも同じ色の帯を付けて「どこから開いたか」が分かるようにする（選ぶ・Esc・× のどれで閉じても元の色に戻る）。ウィンドウは**右クリックしたボタン（Undo）の真下**に出す（画面からはみ出さないよう収める）。行の高さは全行そろえ、余白も少し広げている（透明な 1px 幅のアイコンで高さを指定。日本語の行だけ高くなるのを防ぐ）。行にマウスを乗せると**ツールチップでフルパス**を出す。同名のファイルは一覧では見分けにくい（作者の選択）。
- **Restore From History**: 履歴の新しい方から見て、**いま開いていない最初の 1 件**を一覧なしでタブに開く（閉じたタブの開き直し）。全部開いていれば余白に出すだけ。
- **存在確認**: どちらも実行のたびに存在確認して、無いファイルは履歴から消し、`history=` に書き戻す。
- 検証済み: ユニットテスト（`neo/pathlog.rs` の件数・重複・並び・表示の省略・存在しないパスの除去、`neo/config.rs` の `history=` の読み書き・100 件上限）。未検証: 一覧ウィンドウの操作そのもの（Xvfb での操作は未実施）。

### 行番号欄の自動表示と固定（Pin）

作者の指示（2026-10-25）で、行番号欄は**普通は隠し、必要なときだけ出す**。

- **出す条件**（どれか 1 つでよい）: ① 「固定」されている ② マウスが編集領域の左端にある（隠れているときは左端 10 px の帯、出ているときは行番号欄の幅まで。0.1 秒ごとに座標で見る）。どちらも満たさなければ隠す。文字カーソルの位置では出さない（改行のたびに出たり消えたりしてちらつくため、2026-10-27 に外した）。
- **隠れている間は本文を左へ詰める**（行番号欄の幅を 0 にする）。出ると本文が行番号欄の幅だけ右へずれる。
- **固定ボタン**: ツールバーの `#`（`Pin` の帯は廃止。下の「UI の無駄を削る」参照）。押すたびに 固定 / 解除 を切り替え、固定中はアクセント色。状態の説明はツールチップに出す。
- **保存**: 固定の状態は `gutter_pin=true|false` に保存し、次の起動でも引き継ぐ。既定は false（自動表示）。
- 検証済み（Xvfb + xdotool）: 隠れた状態（本文が左へ詰まる）、マウスを左端へ移すと出る、文字カーソルが行頭だと出る、`Pin` を押すと固定され `gutter_pin=true` が書かれる。未検証: 固定を解除する操作、文字サイズを変えたときの幅、Windows / macOS。

### JSON 整形（Format JSON）

右クリックメニューと Run の右クリックにある。選択範囲を JSON として整形する。選択が無ければ全文。

- 自前の整形器（`neo/json.rs`、依存は足さない）。インデントは 2 スペース、空の `{}` と `[]` は 1 行。数値と文字列は入力のまま出す（桁・`\u` 表記・キーの順を変えない）。
- 厳密な JSON だけを受ける。末尾カンマ・コメント・単引用符・先頭 0 の数値はエラー。入れ子は 256 段まで。
- 不正なときは書き換えず、問題の位置へカーソルを移し、余白に `JSON error 行:桁 理由` を出す。
- 整形は全文の置き換え 1 回なので、元に戻すで戻せる。すでに整形済みなら `Already formatted`。HEX・読込中は対象外。
- 検証済み（Xvfb + xdotool）: 右クリックメニューから整形して保存、不正な JSON は書き換わらず位置がログに出る。ユニットテスト: 入れ子・数値・エスケープ・各種エラー位置・深い入れ子・行/桁。

## 設定ファイル（config.txt）

作者の判断（2026-10-25）で、状態を保存する設定ファイルを持つことにした。設定画面は作らず、**普通のテキストを NeoNote 自身で編集する**形にする（ノンゴールの「設定画面やダイアログを増やさない」とは両立する）。

- **場所**: OS の設定の場所の `config.txt`。フォルダ名はどの OS でも `neonote`。Windows は `%APPDATA%\neonote`、macOS は `~/Library/Application Support/neonote`、それ以外は `$XDG_CONFIG_HOME/neonote`（無ければ `~/.config/neonote`）。実行ファイルの隣に `neonote` フォルダがあるときだけ、そこを使う（持ち歩き用。`neo/config.rs` の `dir_for`）。Linux / macOS で実行ファイル自身が `neonote` のときは同名のフォルダを置けないので、持ち歩き用は使えない。以前の版の `neodir` は読まない（中身も写さない）。フォルダは最初に保存するときに作る。
- **形式**: `キー=値` を 1 行ずつ。`#` の行と空行は無視。
  - `autosave=true|false`: Enable Auto Save の状態。
  - `wrap=true|false`: Word Wrap の状態。
  - `size=数値`: 文字サイズ。空なら既定の 14。範囲は 8〜48（`neo/zoom.rs`）。
  - `font=パス`: 選んだフォントファイル。空なら同梱の NeoFont。
  - `gutter_pin=true|false`: 行番号欄を常に表示（固定）する。false なら、カーソルが左端のときだけ出す。
  - `recent=パス`: 最近開いたファイル。1 行に 1 件、新しい順、最大 10 件。
  - `history=パス`: 過去に読み込んだファイルのパス履歴（View History）。1 行に 1 件、新しい順、最大 100 件。
- **保存のタイミング**: 状態が変わったとき（Auto Save の切替、フォント選択、ファイルを開く・保存する）に書く。終了時にまとめて書かない（強制終了で失わない／エディタで編集中の内容を上書きしない）。書くのは**キーの行だけ**で、コメントや知らない行、キーの位置はそのまま残す。中身が変わらないときは書かない。書けない場所（書込禁止のインストール先など）でも編集は止めず、警告をログに出すだけ。
- **編集**: Load の右クリック → **Open Config** でタブに開く（無ければ今の状態で作る）。普通のタブなので、保存すると（`Ctrl+S`）読み直して即座に反映する（Auto Save・フォント・最近開いたファイル）。開いたまま状態が変わったときは、未編集のタブなら読み直す（編集中のタブには触らない）。`font=` が読めないときは警告して今のフォントのままにする。
- 設定ファイル自身は Open Recent に入れない（開くたびに書き換わって、開いているタブと食い違うため）。
- 検証済み（Xvfb + xdotool）: 初回起動で作成、手で書いたコメント・未知のキーを残したまま更新、`autosave=true` で起動、存在しない `font=` で警告のうえ起動、NeoNote 上で config.txt を編集して `Ctrl+S` すると反映（ログ `config: applied`）。`neo/config.rs` の解析・書き戻し・保存先はユニットテスト。未検証: Windows / macOS、Open Config のメニュー操作そのもの。

## 文字コードの切替メニュー（`Ctrl+E` / Change Encoding）

既定は**自動判定**。メニューは上から次の順に並ぶ。選ばれている行に `●` が付く。

1. **HEX**（バイナリ）
2. **UTF-8**
3. Windows-31J
4. ISO-8859-1
5. US-ASCII
6. **Auto (判定結果)** — 例: `Auto (UTF-8)`、バイナリなら `Auto (HEX)`

- 開いたとき・新規の文書は自動判定（`●` は Auto）。1〜5 を選ぶと、その文字コードに固定して読み直し、`●` がその行に移る。Auto を選ぶと固定を外して、自動判定でディスクから読み直す。
- 自動判定の順序は従来どおり BOM → バイナリ → UTF-8 → Windows-31J → ISO-8859-1。メニューの先頭 2 つ（HEX、UTF-8）は、この判定の優先順位と同じ並びにした。
- バイナリを自動判定で HEX にしたものも「自動」として扱う。そこから HEX を選ぶと、固定の HEX で読み直す。
- 保存先の無い文書は、読み直すものが無いので、文字コードの印だけ切り替える（HEX にはできない）。読み直すときは、未保存の編集があれば確認する（従来どおり）。
- 検証済み（Xvfb + xdotool）: HEX → UTF-8 固定 → Auto → Windows-31J の順に選び、そのつどタイトルとログが切り替わること。

## 第8段階: メモ帳に足りない基本機能（2026-10-25）

一般的なメモ帳と比べて足りなかったものを、影響の大きい順に足している。方針（煩雑な機能は足さない）に合わせ、日時の挿入は入れない。（検索ボックスの常駐・タブの並べ替え・セッション復元は、当初は入れないとしたが、作者の依頼で第12段階に採用した。）

### 改行コード（CRLF / LF）— 確認のみ、変更なし
読み込み → `TextBuffer` → 保存の経路で改行コードは書き換わらない。実際の FLTK `TextBuffer` を通して、UTF-8 / BOM 付き / Windows-31J の CRLF、LF のみ、CRLF・LF・CR の混在、空行の連続、末尾に改行なしを、保存後のバイト列が元と完全に一致することで確認した（使い捨てのテスト。リポジトリには入れていない）。
- 未確認: CRLF のファイルで Enter を押したときに `\n` だけが入り、混在するか。画面上で行末の `\r` がどう見えるか。いずれも GUI の操作が要る。

### Word Wrap
- 右クリックメニュー（編集領域）の **Word Wrap**。チェック式。編集領域を右端で折り返す（`AtBounds`、単語の途中でも折る）。既定は OFF。
- 状態は `wrap=` に保存し、次の起動でも引き継ぐ。config.txt を編集して保存しても反映する。
- 行番号は論理行（折り返した行には付かない）。
- 検証済み（Xvfb）: `wrap=true` で起動して長い行が折り返される。ユニットテスト: `wrap=` の解析・書き戻し。

### Go To Line（Ctrl+G）
- 右クリックメニューの **Go To Line** か `Ctrl+G`（macOS は Cmd）。入力欄 1 つに `12`（行）か `12:5`（行:桁）。`12,5` と `12 5` も可。行・桁とも 1 始まり。桁は文字単位で、`JSON error 12:5` の表示をそのまま入れられる。
- 入力欄に今の位置と全行数を出す。行が多すぎれば最終行、桁が多すぎれば行末（CRLF の `\r` の手前）に移す。選択は解除する。形が違う入力は余白に出して何もしない。
- 計算は `neo/goto.rs`（GUI なしでテスト済み。全角・絵文字の桁、CRLF、丸め、`json::line_col` との往復）。
- 検証済み（Xvfb + xdotool）: `Ctrl+G` で入力欄が出て、`50:3` で 50 行目が表示される。

### 文字サイズ
- `Ctrl++`（`Ctrl+=` も可。テンキーの `+` も）/ `Ctrl+-` で 1pt ずつ、`Ctrl+ホイール`（上へ回すと大きく）、`Ctrl+0` で既定（14）に戻す。範囲は 8〜48。macOS は Cmd。
- 編集領域・行番号（本文より 2 小さく、幅も比例）・Search のハイライトに同じサイズを使う。README / History の別ウィンドウも今のサイズに合わせる。
- 変えるたびに `size=` を保存し、次の起動でも引き継ぐ。既定のときは空（`size=`）。config.txt を編集して保存しても反映する。範囲外の値は範囲内に丸める。
- ホイールは編集領域の上で受ける（ツールバー・タブの上では効かない）。窓でも受けると 1 回が 2 段に数えられたため、窓側では受けない。
- 検証済み（Xvfb + xdotool）: キー・ホイールで増減、`Ctrl+0` で既定、`size=` の保存、見た目の拡大。ユニットテスト: 範囲・丸め・行番号の幅。

### 行・桁の表示
- タイトルに `Ln 12, Col 5` を出す（Path と Words の間）。桁は文字単位で、`Ctrl+G` と `JSON error` の数え方と同じ。
- キー・クリック・ドラッグのあと 0.05 秒にまとめて直す。文字を打ったときは Words の更新と一緒に直る。
- HEX・読込中・8 MiB を超える文書では出さない（全文を数えるため）。
- 検証済み（Xvfb）: 末尾へ移動・矢印キーで行・桁が変わる。全角の桁は文字単位。

### 外部変更の検知
- ファイルを開いた（保存した）時点の更新時刻と大きさを覚えておき、**同じファイルへ保存する直前**に今と比べる。違えば、書く前に確認する（`neo/document.rs` の `Stamp` / `changed_on_disk`）。
- 確認の選択肢: **キャンセル**（Esc）/ **別名で保存**（Enter。相手の変更を消さない）/ **上書き保存**。Enter で選ばれる既定を破壊的でないものにしてある。
- 保存し直した直後は取り直すので、自分の保存で警告は出ない。ファイルが消されていたら警告せずそのまま保存する（作り直すだけ）。別名で保存・新規ファイルは対象外。
- Auto Save は、外部で書き換えられたファイルを**黙って上書きしない**。見送って、余白とログに 1 回だけ知らせる（手動の保存で確認する）。
- 限界: 更新時刻と大きさで見ているので、同じ大きさで時刻が戻る書き換えは見つけられない。保存の直前にしか見ない（編集中に知らせることはしない）。内容の比較はしない。
- 検証済み（Xvfb + xdotool）: 外部書き換え後の保存で確認が出る、Esc で書かない、Enter で別名保存、通常の連続保存で誤警告が出ない。上書きは、選択を固定した検証用ビルドで、書かれてその次の保存で再確認が出ないこと。ユニットテスト: 変更の検出（大きさ・更新時刻）、消えたファイル、記録なし。
- 未検証: 上書き保存ボタンのマウス操作そのもの（Xvfb のクリックが当たらなかったため）、Windows / macOS。

### 未着手
印刷（FLTK でページ分割まで自前で書く必要があり、「必要最低限・シンプル」に収まらないため見送り）。

## 第9段階: 検索の大文字小文字・Tab のインデント・オートインデント（2026-10-25）

メモ帳として足りない基本機能の調査（高優先の 3 件）。操作や設定は増やさず、キーの挙動だけで足す。

### 検索の大文字小文字（スマートケース）
- `Ctrl+F` / `F3` / `Shift+F3`: 探す文字列に **ASCII の大文字が 1 つでもあれば区別、無ければ無視**。小文字で打てば `abc` が `ABC` にも当たり、`ABC` と打てば厳密になる。オプションの切替は置かない。
- 無視するのは ASCII のみ（`neo/replace.rs` の `find_all_smart`）。`É` と `é`、全角英字は区別する。ASCII だけ畳むので文字のバイト長が変わらず、位置をそのまま使える。
- 右クリックの **Search** と **Replace** は従来どおり厳密（「選んだ文字列と同じ箇所」という意味を保つため。選択が `abc` のとき、Search は `ABC` を黄色にせず、Replace も `ABC` を置換しない）。

### Tab / Shift+Tab
- `Tab`: **複数行を選んでいるとき**だけ、選択にかかる行の先頭にタブ文字を足す（空行は飛ばす）。選択が無い・1 行内のときは今までどおりカーソル位置にタブ文字を入れる。
- `Shift+Tab`: カーソルだけでも、その行の先頭のタブ 1 つ（無ければ空白を最大 4 つ）を外す。選択があれば全行。カーソルだけのときはカーソルが同じ文字の上に残る。外す・足す行が無ければ余白に `Nothing to unindent` / `Nothing to indent`。
- 選択は「にかかる行全体」を選び直す。選択が次の行の行頭ちょうどで終わるときは、その行を含めない。1 回の編集なので元に戻すで 1 回で戻る。
- 空白ではなくタブ文字を足すのは、既存ファイルの見た目を勝手に変えないため。幅の設定は持たない。
- 計算は `neo/indent.rs`（GUI なしでテスト済み）。`Ctrl+Tab`（タブ切替）とは別。

### オートインデント（Enter）
- Enter で、**カーソルより左の**行頭の空白とタブを次の行へ引き継ぐ（字下げの途中で押せば、その手前までの分だけ）。選択があれば置き換える。
- **改行コードを行に合わせる**: 今の行（最終行で終端が無ければ前の行）が CRLF なら `\r\n`、そうでなければ `\n`。以前の FLTK 標準は常に `\n` を入れ、CRLF のファイルに LF が混ざった（第8段階の「未確認」の件）。
- CRLF の行末でカーソルが `\r` と `\n` の間に来る（End キーなど）ときは、`\r` の手前に入れる（`\r\r\n` にならない）。
- 全文は取らず、今の行と前の行末だけ読む（大きいファイルでも Enter が遅くならない）。
- HEX・読込中は Tab / Enter に触らない（HEX の本文にインデントを入れると保存できなくなる）。Ctrl / Alt / Cmd を押しているときも触らない。

### 検証
- ユニットテスト（100 件）: `neo/indent.rs`（複数行・空行・CRLF・日本語・選択が行頭で終わる・カーソルだけの Shift+Tab・改行コードの判定・`\r` と `\n` の間）、`neo/replace.rs` の `find_all_smart`（大文字小文字・マルチバイトの後の位置・非 ASCII）。
- Xvfb + xdotool で保存後のバイト列を確認: LF の Enter（`\tab` → `\tab\n\tx`）、CRLF の Enter（End の位置・その 1 つ左のどちらも `\r\n` のまま）、全選択 Tab / Shift+Tab、選択なしの Tab（タブ文字 1 つ）、カーソルだけの Shift+Tab、元に戻す 1 回で戻る、CRLF の Shift+Tab、日本語の行の Enter、Ctrl+F の小文字（`abc` が `ABC` `aBc` にも当たる）と大文字入り（`ABC` のみ）。
- 未検証: IME で変換を確定する Enter（XIM ではキーはアプリに届かない想定だが実機未確認）、Windows / macOS。

## 第10段階: 改行コードの表示と変換（2026-10-25）

必要最低限だけ。設定項目・ダイアログの追加は 1 つだけ。

- **表示**: タイトルの末尾に `| EOL: CRLF`（`LF` / `Mixed`）。HEX では出さない。判定は `neo/eol.rs`。CRLF と LF が両方あれば `Mixed`。単独の CR は改行として数えない。
- **いつ判定するか**: 開いたとき（読込完了）と、変換したときだけ。打鍵のたびには数え直さない（大きいファイルで遅くなるため）。そのため、`Mixed` の文書は、Enter で打っても `Mixed` のまま表示が変わらない（変換すれば変わる）。
- **新規文書（保存先なし）**: 改行の既定は OS に合わせる（Windows は CRLF、他は LF）。Enter は、今の行・前の行に改行の手がかりがあればそれに従い、無いときだけこの既定を使う。
- **変換**: 右クリック → **Convert Line Ending**。`キャンセル / LF / CRLF`（Enter は LF）から選ぶと、全文の改行をそろえる。全文の置き換え 1 回なので、元に戻すで戻せる。HEX・読込中は対象外。
- **文字コード**: 新規文書の文字コードは、今も UTF-8 で始まり、`Ctrl+E` で変えられる（保存先が無い文書は読み直さず、印だけ切り替わる）ので、追加は無い。
- 検証済み: ユニットテスト（`neo/eol.rs` の判定・変換、手がかりが無いときの Enter）。Xvfb + xdotool で、タイトルの `CRLF` / `LF` / `Mixed` 表示、メニューからの CRLF→LF、Mixed→CRLF（日本語を含む）、キャンセルで何も変わらないことを、保存後のバイト列で確認。
- 未検証: Windows / macOS（Windows の既定 CRLF は `cfg!(windows)` で分岐しただけ）。

## 第11段階: 配色の統一とダーク / ライト（2026-10-25）

配色を **5 色のパレット**に統一した（`ui/theme.rs`）。画面の色は必ずここの `color_*()` から取り、色を直したいときは `DARK` / `LIGHT` の定数だけを書き換える。

| 変数 | 役割 | ダーク | ライト |
| --- | --- | --- | --- |
| main | 編集領域・ボタン・選択中のタブの背景 | 43,43,43 | 250,250,250 |
| sub | ツールバー・タブバー・行番号欄の背景（main より一段奥） | 30,30,30 | 232,232,232 |
| accent | 選択範囲・カーソル・押したボタン・固定ボタン・強調の帯 | 0,120,215 | 0,120,215 |
| text | 本文と、選ばれているものの文字 | 200,200,200 | 32,32,32 |
| subtext | 行番号・ツールバーの文字・選ばれていないタブの文字 | 128,128,128 | 105,105,105 |

- 5 色から**混ぜて作る**色（色を足さない）: 選ばれていないタブの背景 = sub と main の中間、一覧の選択行 = main に text を 20% 混ぜた色。accent の上の文字は白（`color_on_accent`）。
- **固定のまま**: 検索のハイライト（黄色の地に黒）。どちらのモードでも読めるため。
- **切り替え**: Run の右クリック → **Toggle Theme**。再起動なしで全体の色が変わり、`theme=dark|light` に保存される（次の起動でも引き継ぐ）。config.txt を編集して保存しても反映する。知らない値や無い場合はダーク。
- **ダークの見た目の変更点（3 つだけ）**: ①本文の文字が subtext（128）から text（200）になった（以前は本文と行番号が同じ灰色だった。本文を text にしたのは「本文は主役の文字」という役割に合わせたため。以前の灰色に戻したければ `DARK.text` を 128 にする。ただしその場合、選ばれているタブの文字も同じ色になる）。②accent の上の文字が 200 → 白。③タブの背景・一覧の選択行が 1 ずれた（36→36、75→74。見分けられない差）。
- コントラストをテストで固定した（`ui/theme.rs`）: text は main / sub の上で 7:1 以上、subtext は 3.5:1 以上、白は accent の上で 4:1 以上。ダーク・ライトの両方。
- 範囲外: FLTK 標準の部品（確認ダイアログ、ファイル選択、スクロールバー）は OS / FLTK の既定の配色のまま。これらまで揃えるには各部品の色を個別に設定する必要があり、次の段階で必要か判断する。
- 検証済み: ユニットテスト 107 件（パレットのコントラスト・混色・config の `theme=` の読み書き）。Xvfb + xdotool で、ダークで起動 → Toggle Theme でライト（ツールバー・タブ・本文・行番号・検索ハイライト・Pin が追従、`theme=light` が保存）→ `theme=light` で起動（`gutter_pin=true` で Pin のアクセント色を確認）→ Toggle Theme でダークへ戻る、をスクリーンショットで確認。
- 未検証: Windows / macOS、config.txt の手編集からの反映（コードは `apply_config` の既存経路）、ライトでの長時間の見た目。

## 第12段階: 検索バーの常駐・タブの並べ替え・セッション復元（2026-10-25）

作者の依頼で、それまで「入れない」としていた 3 つを採用した。理念（軽く早く・省クリック）に合わせ、いずれも設定画面やダイアログを増やさない。「やらないこと」のうち、タブの分割・別ウィンドウ化・一覧のドロップダウン・右クリックメニューは今も入れない。

### 検索バー（常駐）

- **ツールバーの右端**に置く。ふだんは `Find` ボタン 1 つだけで、使うときに開いて `[検索欄] 件数 ← → [置換欄] All ×` を出す（下の「UI の無駄を削る」参照）。専用の行は持たない（縦を食わない）。ツールバーの余白（パスのコピー・短い通知）が残りの幅を使う。実装は `ui/searchbar.rs`（部品。`toolbar::build` の最後に足す）と `app.rs`（`find_*`）。
- 入力するたびに、全ての一致を黄色にして、**いまのカーソル（選択）の位置から先の最初の 1 件**を選ぶ（打ち足しても先へ飛ばない）。大文字小文字はスマートケース（小文字だけで探すときは区別しない。`neo/replace.rs` の `find_all_smart`）。件数欄は `1/4`（位置/総数）・`4 found`・`Not found`。
- キー: `Ctrl+F` で検索バーへ移って全選択（編集領域で 1 行の文字列を選んでいればそれを検索。ただし検索中の文字列と大文字小文字違いだけなら置き換えない）。検索バーの中で `Enter` / `Shift+Enter` が次 / 前、`Esc` と `Tab` が編集領域へ戻る。`F3` / `Shift+F3` は編集領域でも検索バーでも使える。検索バーの中でも `Ctrl+S`・`Ctrl+T`・`Ctrl+Tab` などの全体ショートカットは効く（`Ctrl+Y` だけは編集領域のやり直しにしない）。
- `<` / `>` ボタンは `Shift+F3` / `F3` と同じ。`×` は文字列と強調を消して編集領域へ戻る。ボタンを押してもキーボードフォーカスは編集領域に残る。
- **タブを切り替えても、読込が終わっても、検索中なら新しい文書にも強調を付け直す**（選択は動かさない）。強調は文書ごとのスタイルバッファなので、これをしないと切り替えた先に強調が無い。8 MiB（`LIVE_COUNT_LIMIT`）を超える文書では省く。編集で文字が増減しても強調の位置は更新しない（従来の Search と同じ。打ち直すか `×` で消す）。
- 右クリックの Search（選択と同じ箇所を強調）は、これまでどおり**厳密**（大文字小文字を区別）で、選んだ 1 行の文字列を検索バーにも入れる（F3 で次へ進める）。そのあとの F3 も厳密のまま。検索バーに打ち直すとスマートケースに戻る。
- 入力欄のフォントは編集領域と同じ（フォント変更に追従）。文字の大きさは固定（`FIND_TEXT_SIZE` = 14。Ctrl+ホイールの拡大縮小には合わせない）。ダーク・ライトに追従する。
- 以前の `Ctrl+F` のダイアログ（`find_dialog`）は無くなった。

### タブの並べ替え

- **ドラッグ**: タブを 6px 以上横に動かすとドラッグになる。動かしている間は、落とす先のタブがアクセント色になり、カーソルが移動の形になる。離すと、その位置にタブが入り、そのタブが表示される。バーの外側へ出したときは両端のタブに寄せる（`tabs::drop_slot`）。タブが多すぎて一部しか表示していないときは、表示している範囲の中だけ動かせる。
- **キーボード**: `Ctrl+Shift+PageUp` / `PageDown` で表示中のタブを左 / 右へ 1 つ。端では動かない（回り込まない）。
- ドラッグ中はバーを作り直さない（掴んでいるボタンが消えるため）。離したときに `TabCmd::Move(id, 位置)` をメインループへ返して並べ替える（既存の「バーの作り直しはメインループで」の方針のまま）。位置の計算は `tabs::reorder`（ユニットテストあり）。
- 並び順は文書の一覧（`Ui::docs`）の順で、次のセッション復元にもそのまま使う。
- 中クリックで閉じる動作は変えていない（左ボタンのドラッグだけが並べ替え）。

### セッション復元

- 終了時に開いていたタブ（保存先のあるファイル）と、表示していたタブを `config.txt` に残し、**引数なしで起動したとき**に同じ並びで開き直す。表示するのは前回表示していたタブ。起動の流れは普通に開くのと同じで、読込は非同期。
- 書式: `session=<パス>`（左から順に 1 行ずつ。最大 50 件。重複は 1 つ）と `session_active=<パス>`。アプリが書き戻すときは、この 2 つのキーの行だけを書き換える（`config::render`。コメントや知らない行は残す）。
- 保存するのは**パスだけ**。未保存の内容は残さない（終了時は未保存のタブを必ず確認するため、保存か破棄が済んでいる）。保存先の無い Untitled・設定ファイル自身は入れない。HEX で開いていたタブも、次はふつうに（自動判定で）開く。
- 見つからなくなったファイルは飛ばし、余白に `Restored 3 tabs (1 missing)` と出す。次に書き戻すときに一覧からも消える。
- **書き込むタイミング**（クラッシュしても残るよう、終了時だけでなく変化のたびに）: ファイルの読込完了・名前を付けて保存・タブを閉じる・並べ替え。どれも既存の `persist()` に乗せていて、内容が変わらなければ書かない。表示しているタブの変化だけは、タブを切り替えるたびに書き込まないよう、終了時にまとめて書く（`Ui::quit`）。そのためクラッシュした場合、次に表示するタブは直前の保存時のものになることがある。
- **最後のタブを閉じて終了したとき**（`Ctrl+W` / `×` で最後の 1 つを閉じる）は、セッションを空にする。次の起動では何も開き直さない。ウィンドウの `×` と Exit は、開いているタブをそのまま残す。
- **引数つきで起動したウィンドウ**（ゲームからのドロップなど）は、セッションを復元も保存もしない（`session_owner`）。ドロップのたびに別プロセスが起動するので、これを許すと開き直しのたびに前回のタブが増え、終了時にセッションが上書きされるため。引数つきウィンドウが設定を書き戻すときも、保存済みの `session` はディスクから読み直して、そのまま残す。引数なしのウィンドウが複数あれば、あとに閉じた方が勝つ。
- 設定ファイルをエディタで保存して反映するとき（`apply_config`）、`session` の行は読み込まない（起動中のタブの状態が正）。

### 検証

- ユニットテスト 110 件（既存 107 + `config` のセッション往復・重複・上限・置換位置、`tabs` の `drop_slot` と `reorder`）。
- Xvfb + openbox + xdotool で確認: 検索バーの表示、入力するたびの強調と最初の 1 件の選択（`1/4`）、`Enter` / `Shift+Enter`（`4/4` から先頭へ折り返し）、`Esc` → `F3`、タブを切り替えたときの強調の付け直し、`×`、日本語の検索、検索バーの中の `Ctrl+T` と `Tab`、ライトテーマの配色、タブのドラッグ（落とし先の強調と並べ替え後の並び）、`Ctrl+Shift+PageDown`、セッション（config を手書きして起動 → 欠けたファイルの除外 → 前回の表示タブの復元 → ウィンドウ × で保存 → 引数つきウィンドウが保存を変えないこと → 再起動で復元 → 最後のタブを閉じてセッションが空になること）。
- 未検証: ファイルのドロップ、Windows / macOS、数十個のタブでのドラッグ、`Ctrl+Shift+PageUp/Down` が OS・入力方式に奪われる環境。


## UI の無駄を削る: タブ直下の帯・検索バーの開閉・ツールチップ（2026-10-25、第14段階の続き）

作者の依頼。方針は「縦と横の無駄を作らない」「状態の説明はツールチップへ」。

- **タブの下の帯を廃止**: 行番号欄の固定ボタン `Pin` のために、編集領域の上へ高さ 16 px の帯を置いていた。この帯が本文の表示域を縦に削っていたので、**固定ボタンをツールバーの `#`（幅 24 px、`Run` の右）へ移して帯ごと消した**。編集領域はタブバーの直下から始まる。固定中はアクセント色、説明（自動表示 / 常に表示）はツールチップ。マウスが「行番号欄の上」にあるかの判定は、帯ではなく編集領域の上端から行う。
- **検索バーは使うときだけ開く**: 閉じているときは `Find` ボタン（幅 44 px）だけ。開くと `[検索欄 120] 件数 70 [←] [→] [置換欄 90] [All] [×]`（ツールバーの 1 行の中で出し入れするので、縦は増えない）。開くのは `Find` ボタン・`Ctrl+F`・`Ctrl+H`・右クリックの Search / Replace。`Esc` は閉じるだけ（文字列と強調は残るので `F3` で続けられる）。`×` は文字列と強調を消して閉じる。閉じている間の `F3` は、件数（`2/5`・`Not found`）を余白に一瞬だけ出す。
- **置換**: 置換欄で `Enter`（か `All`）を押すと、検索中の文字列（強調している箇所）を全て置換欄の文字列にする。全文を 1 回だけ読み、1 回の編集として書き戻す（元に戻す 1 回で全て戻る）。Ctrl+H / 右クリックの Replace で選んだ文字列は、これまでどおり**厳密**（大文字小文字を区別）で探す。検索欄を打ち直すとスマートケースに戻る。複数行の選択だけは検索欄に入らないので、従来の入力ダイアログを残した。実装の純粋な部分は `neo/replace.rs` の `apply_replace`（テストあり）。
- **ツールチップに寄せた情報**: `#` の状態、`Find` ボタン（検索中の文字列の件数つき）、検索欄（件数 + キー操作）、`←` `→` `All` `×`、置換欄の使い方。件数の欄は、入力しながら見えないと困るので開いている間だけ検索バーに残した（ツールチップは、マウスを乗せないと出ないため）。
- **幅**: 開いたときに入りきるよう、ツールバーのボタンを 64 → 50 px、ウィンドウの既定の幅を 960 → 1000 にした。狭くすると余白（通知）から先に縮み、検索バーは縮まない。

### 画像のメタデータと pdf の文字を編集する（stage 20、2026-10-26）

作者の依頼: 「本質はテキストエディタなので、画像のメタデータや pdf の文字を編集したい。ただし軽量に反する・依存が複雑になるなら不要」。判断は次のとおり。**依存は増やさない**。

- **画像のメタデータ（実装）**: チップのメニュー（画像の Preview 中）の `Edit Metadata (text)` で、メタデータを `キー=値` の行として **新しいタブ**（`pic.png.meta`）に開く。編集して `Ctrl+S` すると、画像の本体（ピクセル）には触れず、メタデータの部分だけ差し替えて画像へ書き戻す（`write_atomic`）。`Save As` を選ぶと、ふつうの文字として別ファイルに保存する。
  - 対象は **PNG の tEXt と圧縮なしの iTXt**（Title / Author / Comment など。行の追加・削除・修正が自由）と **JPEG のコメント（COM）**（キーは `comment` のみ、複数行 = 複数コメント）。Latin-1 に収まらない値（日本語など）の PNG は iTXt（UTF-8）で書く。値の改行は `\n`、`\` は `\\`。キーが `=` を含む・空・80 文字以上などは保存前にエラーにする。
  - **編集しないもの**: EXIF（撮影日時・GPS・カメラ）、zTXt・圧縮 iTXt、ICC プロファイルなど。書き戻しでそのまま残す。EXIF は 2 進の構造（IFD・オフセット）で、壊さず編集するには専用の部品が要るため、軽量の方針に合わないと判断した。
  - 実装: `neo/imgmeta.rs`（GUI なし・依存なし。PNG のチャンク・CRC32・JPEG のセグメントを自前で扱う。テストあり）。`State::meta_of`（この文書が編集している画像）、`Ui::save_meta` / `open_meta`。JFIF は SOI の直後に残し、コメントはその後ろへ置く。
- **pdf（本体の編集は実装しない）**: pdf の中の文字を直接書き換える機能は入れない。pdf の文字は、フォントの部分集合・字送り・レイアウトと結びついた命令列で、文字を差し替えるとレイアウトや文字化けが壊れやすく、まともにやるには PDF の描画・フォント処理が要り、軽量の方針（依存最小・単一バイナリ）に反する。代わりに、チップのメニューの `Text in New Tab` で **取り出した文字を編集用の新しいタブ**に開く。コピー・修正・`Save As` で .txt や .md にできる。元の pdf は変えない。
- 検証: ユニットテスト 141 件（既存 132 + `imgmeta` 9）。Xvfb で、tEXt 入りの PNG を開く → Edit Metadata → 行を足して Ctrl+S → **PIL で読み直して追加が反映され、画像サイズ・既存の項目が変わらないこと**を確認。pdf の `Text in New Tab` で 2 ページ分の文字が新しいタブに出ること。
- 未検証・既知の制限: JPEG の実ファイル（テストは自作のバイト列のみ）、EXIF が大きい JPEG、巨大な PNG（読んで書き直すので、画像全体をメモリに載せる）、他のソフトが付けた独自のチャンク（そのまま残す）、Windows / macOS、メタデータを書き戻した直後に元画像のタブがディスクの変化を検知する挙動。
- 次にやること: GIF / WebP の扱い、EXIF の読み取り専用表示（編集はしない）が必要かを作者が判断する。


### フォルダ・zip の階層表示と名前変更（stage 21、2026-10-26）

作者の依頼: 「ドラッグ&ドロップや読み込みがフォルダ・zip のとき、7-Zip のプレビューのように階層と名前が見えるようにしたい。できればリネームまで」。方針は **依存を増やさない**（zip の目録の読み書きは自前。`encoding_rs` は本体がすでに使っている）。

- **開く**: `open_path` → `load_into` が、フォルダまたは `.zip` を見つけたら本文を読まず、別スレッドで一覧だけを取る（`Msg::Archive`）。zip は末尾と目録だけを読む（`list_zip_file`）ので、大きな zip でも全体は読まない。zip として読めないファイル（壊れている等）は、ふつうに開き直す。メニューに `Open Folder...` を足した（ドロップ・引数・最近開いたもの・前回のタブの復元も同じ入口）。
- **表示**: Preview（`Kind::Archive`）。フォルダが先・名前順のツリーで、サイズの列（zip は圧縮後も）、フォルダのサイズは中身の合計。目録にない親フォルダも補う。Preview は読み取り専用で、Text・HEX には切り替えない。`Ctrl+S` は何もしない。
- **名前変更**: チップのメニューの `Rename (text)` で、パスの一覧（1 行 1 パス、フォルダは末尾 `/`）を新しいタブ（`name.rename`）に開く。名前だけを直して `Ctrl+S`。行の追加・削除はできない（行数が違えば書かずにエラー）。`Save As` は、ふつうの文字として別ファイルに書く。
  - フォルダの行だけを直したら、その中の（行を直していない）項目も一緒に移る。子の行を自分で直したものは、その通りにする。
  - 使えない名前（`..`・絶対パス・`\` `:`・空の階層・重複・ファイルとフォルダの衝突）は、書く前に止める。変えていない行は検査しない。
  - **zip**: 圧縮データは 1 バイトも変えず、名前と目録だけを書き直す（`write_atomic`）。変えた名前は UTF-8（フラグ付き）で書き、Info-ZIP の Unicode Path（0x7075）は外す。変えない項目は名前のバイトもそのまま。変えなければ全体がバイト単位で同じ。
  - **フォルダ**: 一時の置き場を経由して動かす（入れ替えも可）。途中で失敗したら動かしたものを戻す。行き先がすでにある・リンクの中に入る場合は、動かす前に止める。空になった元のフォルダは消す。
  - 開いたあとに中身が変わっていたら（一覧が食い違う）、何もせずエラーにする。成功したら、開いている Preview と編集中の一覧を新しい状態にそろえる。

### 2. 横スクロールバーが、はみ出しがなくても全幅のつまみで出る（hello.txt・long.txt・HEX）

- **測るタイミング**: 0.1 秒のタイマー（`poll_mouse`）から呼び、文書・文字数・幅・文字サイズ・フォント・折り返し・行番号欄の幅のどれかが変わったときだけ測り直す。同じ文字数での書き換え（置換など）は、次に上の条件が変わるまで反映されない。
- **制限**: 512KB を超える文書は測らず、従来どおり FLTK 任せ（横が常に出ることがある）。長さが最長の行の 1/4 未満の行は測らないので、文字の幅が極端に違う混在では判定がずれることがある。

- **わかったこと**: 設定ファイル（実行ファイルの隣の `config.txt`）に `wrap=true` が残っていると、折り返しのため横スクロールバーは出ない。HEX も、ウィンドウが狭いと折り返される。検証の途中でこれに引っかかった（撮影前に `wrap=false` に戻して撮り直した）。

### 文字コードに UTF-16LE / UTF-16BE / EUC-JP を追加（調査の優先度 2、2026-10-26）

作者の依頼（調査結果を記録したら、優先度が高くすぐ実装できるものを実装する）。優先度 1 の xlsx / ods は第26段階で済みなので、次の「UTF-16・EUC-JP」を実装した。**`CLAUDE.md` の指示どおり、ビルドもテストも GUI での確認もしていない（すべて未検証）。**

- **`neo/encoding.rs`**
  - `Encoding` に `EucJp` / `Utf16Le` / `Utf16Be` を追加（表示名は `EUC-JP` / `UTF-16LE` / `UTF-16BE`）。復号は `encoding_rs` の厳密な復号（不正な位置を返す）を `decode_rs` に切り出して共用。Windows-31J の処理は同じ関数に載せ替えただけ。

  - **自動判定の順**: UTF-8 BOM → UTF-16 BOM（**本文が厳密に UTF-16 として読めるときだけ**。FF FE 00 00 で始まる UTF-32 は対象外）→ BOM なし UTF-16 の推定 → バイナリ（HEX）→ UTF-8 → Windows-31J → **EUC-JP** → ISO-8859-1。
  - **BOM なし UTF-16 の推定**（`guess_utf16_without_bom`）: ASCII の多い UTF-16 は 2 バイトの片方が 0 になる。対の 3 割以上が同じ向きの「文字 + 0」で、逆向きが 1 つも無く、全体が厳密に復号でき、制御文字（改行・タブ以外）が出ないときだけ採る。**日本語だけの BOM なし UTF-16 は 0 が出ないので推定できない**（手動で選ぶ）。
  - **EUC-JP の自動判定は「次点」だけ**: Windows-31J として読めなかったときに EUC-JP として読めれば EUC-JP にする。EUC-JP と Windows-31J の両方で読めるバイト列は Windows-31J を選ぶ（区別が付かないため）。EUC-JP のファイルが Windows-31J として化けて開くことはあり得るので、その場合は文字コードのメニューから選ぶ。
- **`neo/document.rs`**: BOM の判定を文字コード別に（指定して開いたときも BOM を外し、保存時に付け直す）。エラー位置は BOM の長さ分を足す。
- **`app.rs`**: 文字コードのメニューに EUC-JP / UTF-16LE / UTF-16BE を追加（並びは UTF-8 / Windows-31J / EUC-JP / UTF-16LE / UTF-16BE / ISO-8859-1 / US-ASCII）。タイトル・タブの表示は BOM 付きなら `UTF-16LE BOM` のように出す。**新しい文書で UTF-16 を選んだら BOM つきで保存する**（BOM が無いと再度開いたときに向きが分からないため）。

  - **tar の読み方**（`list_tar`）: 512 バイトのヘッダーを順に読む。検査和（符号なし・符号ありのどちらでも可）が合わなければ、1 つ目なら「tar ではありません」、途中なら「壊れています」の Err。全部 0 のブロックで終わる。本文が途中で切れていれば Err（一部だけ出して黙って続けることはしない）。大きさは 8 進と GNU の 2 進表記の両方を読む。
  - **長い名前**: ustar の `prefix`（マジックが `ustar\0` のときだけ。GNU 形式の `ustar  ` では使わない）、GNU の `L`、PAX の `path`。PAX の `size`（大きなファイル）も読む。これらは直後の 1 項目だけに効く。`g`（グローバル PAX）と `K`（長いリンク名）は読み飛ばす。
  - **出すもの**: ファイル（`0` / 空文字 / `7`）とフォルダ（`5`、名前が `/` で終わるもの）。**リンク（`1` `2`）・デバイス・FIFO は出さない**（`list_dir` がシンボリックリンクを出さないのと同じ）。先頭の `/` と `./` は外し、ルート自身（`./`）は出さない。親フォルダの項目が無くてもツリーは `build_tree` が補う。
  - **名前の文字**: UTF-8 として正しければ UTF-8、だめなら Windows-31J として読めれば Windows-31J、さらにだめなら Latin-1。zip と違い `\` は `/` に直さない（tar では名前の一部）。

## CRLF の文書を LF で持つ（Windows での確認から）

- Windows では FLTK が行末の `\r` を「CR」の印として描いていた。CRLF だけの文書は、読み込みのときに LF にして持ち、保存のときに CRLF へ戻す（`on_loaded`・`save`）。LF / CRLF の変換は、本文を LF にそろえて改行コードの記録だけを変える。Enter は常に `\n` を入れる。
- CRLF と LF が混在する文書（Mixed）は、元のバイトを保つため今まで通り `\r` を持つ（印が出る）。
- 新しい文書（Windows では CRLF）と、pdf・文書から取り出した写しは、保存すると CRLF になる。
- 検証済み（Windows 11）: CRLF の UTF-8 で印が出ない、行末への追記・行の途中での Enter・末尾への追記を `Ctrl+S` で保存して、全行が `\r\n` のまま。ユニットテスト 255 件。未検証: CRLF 文書への CRLF を含む貼り付け、Windows-31J の CRLF の保存、macOS。

## NBT（level.dat・.mca）の編集（2026-10-27）

- `.dat`・`.dat_old`・`.nbt`・`.schematic`・`.schem`・`.litematic` は、NBT として読めれば SNBT（/data と同じ書き方）の文字で開く。保存すると開いたときと同じ包み方（gzip・zlib・なし）と根の名前で NBT に戻す。SNBT の書き間違いは保存せず、行・列を示してそこへカーソルを移す。NBT として読めなければ今まで通り（文字か HEX）。

- Format と Encode は、右パネルの幅を 96 : 104 に分ける（`tabs::view_chip_width`）。以前の 96 + 104 = 200 px と同じ比で、既定の幅では見た目は変わらない。
- 右パネルが隠れている間も幅は変えない（行番号欄が隠れていても、左の押しピンの幅が変わらないのと同じ）。
- 幅は右パネルの左の境目のドラッグに加えて、Format の左の境目のドラッグでも変えられる（左の `#` の右の境目と対。`tabs::add_side_grip`）。保存は今まで通り `side_w`。
- タブバーの幅は、2 つのチップの実際の幅を引いて決める（定数ではなく `chip.w()` / `view_chip.w()`）。

## フォルダ・zip のタブの検索（v2.1.77 の後）

フォルダ・zip を木（Preview）で見ているタブでは、検索バーは本文（編集領域は隠れていて、中身は名前の一覧）ではなく、一覧の中の名前を探す（`App::archive_tree_active`）。Text に切り替えて名前を編集している間は、今まで通り本文を探す。

- 探し方は `archive::filter_tree`（GUI なし・テスト 1）。階層（`build_tree` の結果）から、名前が検索語を含む項目と、その親のフォルダだけを残した木と、一致した項目の道筋（上から下・表示の順）を返す。大文字を含まなければ ASCII の大文字小文字を無視する（本文の検索と同じ）。検索語に `/` があれば、根からの道筋全体（`data/foo`）で探す。末尾の `/` は無視する。フォルダ名が一致しても、中身は一致したものしか出さない。
- 木の描画は `NbtTree::show_archive(…, find)`。`find` が空でなければ絞った木を作り、全て開く。一致した項目は文字を濃く、一致の親は薄く出す。一致の道筋は `hits` に持つ。`step_hit(forward)` が、選んでいる項目の次・前の一致を選ぶ（選びが一致の外なら先頭・末尾から。端は反対側へ戻る）。
- 絞っている間の開閉は保存しない。絞った木は全て開くので、そのまま `tree_open` に保存すると、絞りを外したときに全て開いたままになる。`open_paths` は、絞る前の開き方（`base_open`）を返す。
- 絞りの元は `last_search`。`render_archive_tree` は常にそれを使うので、別のタブへ移っても、戻っても、検索中の絞りは一貫する。入力のたびに木を作り直す（項目は 2 万まで）。件数は本文の検索と同じようにツールチップに出す（0 件は赤い Not found）。
- 検索欄の × は絞りを外して一覧を元に戻す。Esc は検索バーを閉じるだけで、絞りと検索語は残る（本文の強調が残るのと同じ）。
- 置換は、一覧では使えない（名前の変更は Rename の編集で行う）。置換欄・ボタンを使うと「置換できません」と出す。
- ファイルの本文も探す（`archive::search_contents`・テスト 2）。フォルダと zip だけ（tar 系は目録しか読めないので名前だけ）。1 ファイル 4 MB（`CONTENT_MAX_FILE`）まで。先頭 8 KB に NUL があるファイルはバイナリとして飛ばす。文字は UTF-8（BOM は除く）→ UTF-16（BOM 付き）→ Shift_JIS の順に読み、どれでも読めなければ飛ばす。大文字小文字は名前と同じ規則（大文字を含まなければ ASCII を無視）。zip は `each_zip_file` が目録を 1 回だけ読んで順に展開する（1 件ずつ `read_entry` すると目録を毎回読み直して、項目数の二乗になる）。
- 本文の検索は裏のスレッドで行う。流れは、入力 → 名前の一致で木をすぐ作る（`archive_find`）→ 250 ms 待ってから本文を探す → 結果を `Msg::ArchiveContent` で受け、木を作り直す（`on_archive_content`。選んでいた項目は `NbtTree::select_path` で戻す）。打ち直したり別のタブへ移ったりすると世代（`arch_gen`）が進み、前の検索はファイルの区切りで打ち切る。結果は `arch_content`（文書の id・検索語・パス）に 1 つだけ持ち、検索語か文書が違えば使わない。一覧を読み直したときと名前を変えたときは捨てる。
- 本文だけが一致したファイルは、本文の検索が終わるまで木に出ない。検索語を 1 字足すたびに、いったん消えて、終わると戻る。


## .mcfunction の呼び出し元ヘッダー（v2.1.77 の後）

Run のサブメニューの **Header**、または編集領域の右クリックの **MC Header**。開いている `.mcfunction` の先頭に、次の形のヘッダーを作る（既にあれば作り直す）。VS Code 拡張 `mcfunctionHeader` の機能の移植で、`neo/mcheader.rs`（GUI なし・依存なし）に置いた。

```
# 命名：tick
# 説明：
# >/function demo:main
# >/advancement demo:start
# >/enchantment demo:ench
# >/tag/function #minecraft:tick
# =/function demo:sub/tick
```

- **理念との関係**: マイクラのデータパックを直すのに直接役立つ、という採用基準（「この理念からの設計上の帰結」）を満たす。ファイルツリーやプロジェクトは持たないので、探す範囲は「開いているファイルのパスから決まるデータパック（`data` の親）」だけにした（VS Code 版のワークスペース全体の検索はしない）。メニューの 1 項目として呼ぶだけで、プラグイン基盤・常駐処理・新しい依存は足さない。
- **ID の求め方**: 外側の `data` から順に `data/<名前空間>/function(s)/…` の形になる所を探す。`function/data/init.mcfunction` のように関数の下に `data` フォルダがあっても名前空間を取り違えない（VS Code 版は最後の `data` を使っていて取り違えた）。
- **探す物**: 他の `.mcfunction` の `function ns:id`（コメント行・引用符の中・say などの自由な文は除く。行末の `\` で続く行は 1 つのコマンド。ID は `[A-Za-z0-9_.-/:]` の連なりを丸ごと比べるので `ns:foo` は `ns:foo-bar` に当たらない）、advancement の `rewards.function`、enchantment の JSON の中の文字列の完全一致、function タグの `values`（`#` の入れ子は、循環があっても行き着ける物を全部拾う）。advancement・enchantment・タグはそれぞれの決まったフォルダの JSON だけを読む（VS Code 版は全 JSON を読み、無関係のファイルを `?:` つきで出していた）。`function` と `functions`（旧形式）の両方に対応する。
- **ヘッダーの更新**: `# >/…` `# =/…` `# >(…` の行だけを作り直し、命名・説明・独自の項目（`# 実行条件：…`）と、`#> 備考` のような普通のコメントは書いたまま残す。命名が無い時だけ命名と説明の既定値を補う。先頭の `#` の塊に作り直す行か `命名` `説明` が無い時は、コードの説明コメントとみなして巻き込まず、その手前に新しく入れて空行で区切る。呼び出し元は自然順（`f2` の次が `f10`）。2 回続けて実行しても変わらず、変わらない時は `Header is up to date`。
- **動作**: 検索は 1 パスで、見つけたファイルは 1 回だけ読む（1 ファイル 8 MiB・20 万ファイルまで）。置き換えは先頭部分の 1 回の編集なので「元に戻す」で戻せる。保存してある `.mcfunction` だけが対象（未保存のタブの本文は読まず、ディスク上のファイルを読む）。
- **検証**: ユニットテスト 10 件（ID・`data` フォルダの取り違え・境界・コメント / say / 引用符・タグの循環・自然順・ヘッダーの新規 / 更新 / 冪等・一時フォルダでの一連の検索）。ビルドとテストは通した。**画面での確認（Xvfb でのメニュー操作）は未検証。** フォルダ右クリックでの一括生成は入れていない（NeoNote にフォルダ操作の入口が無いため。必要なら別途）。

### ID から開く（Shift+クリック）

本文の `ns:path`（`function neofunction:asset/bossbar/hide`、ヘッダーの `# >/function demo:main` など）を Shift + クリック（Ctrl / Cmd + クリックも同じ）すると、指すファイルを新しいタブで開く（空のタブなら、そこに開く）。マウスを約 0.3 秒乗せると、小窓（`peekwin::Content::Link`）に ID と「Shift+クリックでこのファイルを新タブで開く」を出す。指す先が無ければ「ファイルが見つかりません」。色・文字・時刻・画像の値の見回りを先に見て、どれでもなければ ID を調べる。VS Code 拡張 `flying_elytra` のリンク機能の移植で、`neo/mcheader.rs` の `reference_at`（行の中の ID を見分ける）・`data_dirs_near`・`resolve`（ファイルを探す）が GUI なしの部分。

- 種類は手前の語で決める: `function` → 関数、`advancement`、`enchantment`、`#` → 関数タグ。手前に何も無い裸の `ns:path` は、関数 → advancement → enchantment → loot_table・predicate・item_modifier・recipe → タグ の順で、先に見つかった物を開く。`function` と `functions`（旧形式）の両方を探す（VS Code 版は単数形だけだった）。
- 探す場所: 開いているファイルの上の階層の `data` と、そのデータパックの隣のデータパックの `data`（近い順）。別のパックにある名前空間も開ける。深くは探さない。パスに `..` や空の区切りがある書き方は ID とみなさず、フォルダの外へは出ない。
- ID でない所の Shift+クリックは、ふつうの範囲選択のまま。ID なのに無ければ `Not found: ns:path` と出す。HEX・読込中・Preview では働かない。
- 未検証: 画面での操作（Xvfb）。ユニットテストは ID の見分け・`..` の拒否・隣のパックの検索・種類ごとの探し方。
